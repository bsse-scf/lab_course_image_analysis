This repo contains course material for the Image Analysis module of the Lab course of the Single Cell Facility of D-BSSE at ETH Zurich.

## Notes

- The schedule is only a sketch of an outline and serves to communicate instructor intentions. It can be improved
- The course should be pedagogically sound and useful, and simple at the same time.
- In terms of example data, datasets from the BBBC (Broad Bioimage Benchmark Collection) should be used (or subsets thereof)
- if applicable, useful existing course materials should be leveraged from high quality sources

## `detailed_schedule.md` is the source of truth

`detailed_schedule.md` records what is taught, in what order, and where. **It
leads; the material follows.** To change the course:

1. Edit `detailed_schedule.md` — move a topic, rename a section, add one.
2. Change the notebooks and sheets to match.
3. `pixi run check-schedule` until it passes.

The **Section** column of each table must match the level-2 headings of the file
it describes, exactly and in order (`Recap`, `If you finish early` and
`Preparation` are structural and excluded). The check runs in `pixi run test`,
so the two cannot drift apart unnoticed.

`pixi run check-schedule --list` prints the headings as they currently are,
which is the quickest way to resync after restructuring a notebook.

Note that section *headings* are what is checked — not the prose beneath them.
Moving a topic between notebooks means updating the "Where each concept first
appears" table at the bottom of the schedule too, and that part is on you.

## Authoring conventions

These are binding for all course material in this repo.

### One source of truth per topic

Each Python topic has exactly one **executable walkthrough notebook** in `notebooks/`, and
that notebook goes directly into `_toc.yml`. Concept pages under `book/python/` carry
motivation, figures, references and slide embeds — **never code fences that duplicate
notebook code**. If you are pasting code into a concept page, it belongs in the walkthrough.

The previous edition split each topic into a 1700-line non-executed markdown chapter plus a
1 KB exercise stub. Nothing kept them in sync and nothing executed, so a walkthrough that
pointed at a non-existent data directory sat broken and unnoticed. Do not reintroduce that
split.

### Exercises are generated, never hand-written

Author the *solution* in `notebooks/NN_topic_ex_solution.ipynb` (gitignored) using these
markers, then run `pixi run make-exercises` to emit `notebooks/NN_topic_ex.ipynb`.
Solutions sit beside the exercises, not in a subdirectory, so both resolve
`from course import DATA` and any relative data path identically:

```python
# --- your turn ---
### BEGIN SOLUTION
thresh = threshold_otsu(nuclei)
mask = nuclei > thresh
### END SOLUTION
### BEGIN PROMPT
# thresh = ...   # TODO: compute an Otsu threshold for `nuclei`
# mask = ...     # TODO: turn the threshold into a boolean mask
### END PROMPT
```

Never edit a generated `*_ex.ipynb` by hand — CI regenerates and diffs them.

Prefer `# TODO:` comment lines to a bare `...` (which is valid syntax, so the notebook
"runs" and then fails cryptically three cells later) and to `raise NotImplementedError`
(correct, but hostile to beginners who have never read a traceback).

### Hints use `<details>`, not MyST admonitions

```html
<details>
<summary>Hint 1 — which function?</summary>

`skimage.filters.threshold_otsu` returns a single scalar. Compare the image against it.
</details>
```

A `{admonition} :class: dropdown` renders beautifully on the built site but shows as raw
directive text inside JupyterLab — which is where students actually sit for two days.
`<details>` collapses correctly in both. Ladder hints: nudge → function name → near-answer.

### Notebook house rules

- Open with a fixed header cell: title, approximate duration, learning goals, data used.
- Reach data via `from course import DATA`, never a bare relative path.
- Every notebook must run end-to-end in the CI environment in under five minutes.
- Keep each napari call in its own cell so a display-less CI run can skip it cleanly.
- Notebooks are flat and numbered in `notebooks/`. Do not group them into per-session
  subdirectories: that makes exercise and walkthrough paths differ in depth from `data/`,
  which reliably confuses students.

### No JVM in the Python track

Weka is trained *and* applied in Fiji on day 1. Day 2 reads the exported probability maps
and label images back in with `tifffile`. Do not add `pyimagej`, `openjdk` or `maven` to the
environment, and do not call Fiji from a notebook.

### Never delete `data/*/weka/`

`data/bbbc020/weka/bbbc020_cells.model` is trained interactively in Fiji and
**cannot be regenerated by any script**. Rebuilding a dataset means removing and
re-fetching `images/` and `gt/` only — never `rm -rf data/bbbc020`, which takes
the classifier with it. `scripts/fetch_data.py` writes into the dataset
directory without clearing it, and warns if the model has gone missing.

### Data

- Everything in `data/` is committed as an ordinary git blob. **There is no git-lfs**,
  so the only thing keeping the repository small is the size limit: nothing in `data/`
  may exceed **512x512** pixels. `scripts/fetch_data.py` enforces this on everything it
  writes.
- Downscaling goes through `scripts/downscale.py`, which has separate paths for intensity
  images (anti-aliased) and label images (`order=0`, nearest-neighbour). Resizing labels
  with interpolation produces plausible-looking ground truth with garbage at every object
  boundary and silently invalidates the segmentation-metrics exercise. `save_labels()`
  warns if downscaling drops an object entirely.
- **Downscaling changes every hardcoded number in the notebooks** - pixel coordinates,
  crop windows, `max_size` area cuts, watershed `min_distance`, filter sigmas. If the
  data is ever rebuilt at a different size, re-derive these rather than scaling them by
  eye, and re-run every notebook.
- Every file added to `data/` gets a row in `data/MANIFEST.md` with its source, licence and
  sha256. `pixi run test` verifies them.
- `../2025_homework` contains graded student submissions with names in the clear. It is out
  of scope for this repo: do not read it, glob it, or copy from it.


## Further notes
- The course is designed for Biotechnology Master students at D-BSSE who have varying levels of experience in image analysis
- we assume that students are mostly beginners in image analysis and programming
- The course is designed to be hands-on, with a focus on practical exercises and real-world applications of image analysis techniques
- It's a two day course
- In the microscopy part of the lab course (which students complete after this module), students acquire images which they will need to analyse (see homework.md for details)
- On the afternoon of the second day, students will work on a challenge (see challenge.md for details) that will require them to apply the skills they have learned in the course to a real-world image analysis problem
- the course aims to prepare students to autonomously complete the challenge and homework, and should give them a good first exposure to the basic and most important concepts in bioimage analysis
- data and exercises should include both
  1) a dataset and workflow which serves as a guiding motivation and example. This should be: images - preprocessing - segmentation - feature extraction - analysis and visualization
  2) small and fun exercises which allow students to explore and learn the concepts with some diversity and creativity
- images are kept small: nothing in `data/` exceeds 512x512 pixels. `scripts/fetch_data.py`
  downscales everything it emits, using `scripts/downscale.py`
- solutions to the exercises are git ignored and not included in the repo, but can be provided to students upon request

### Teaching dynamics
  - Fiji part:
    - For each topic bundle:
      - concept explanation
      - interactive demonstration
      - exercises
        - format: markdown files with written out exercises and instructions, as well as example images
  - Python part:
    - For each topic bundle:
      - concept explanation
      - jupyter notebook to go through with students
      - exercises
        - format: jupyter notebooks with blanks for students to fill in, with hints and explanations

- practical part:
  - first, students will learn image basics and basic segmentation / feature extraction in Fiji
  - then, they will learn how to use Python for image analysis. Switching to Python is motivated by the need for flexible and reproducible workflows, as well as the need to batch process

## Computational environment

- Students clone the repo and install using pixi
- Data is included in the repo as ordinary git blobs - no git-lfs, so a plain
  `git clone` is all a student needs. Keeping every image at 512x512 or below is what
  makes that viable.
  The one exception is the day-2 challenge dataset (`plate01.nd2`, ~3.3 GB), which is
  distributed separately - see `book/setup/download_data.md`
